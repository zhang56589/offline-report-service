# Report Service 项目协作规则

> 适用范围：本项目全部对话与代码修改。本文件优先级高于模型默认习惯。
> 项目定位：Spring Boot 2.7.18 + MyBatis-Plus + EasyExcel + Quartz + Redisson 的报表异步导出任务服务。

---

## 一、工作流程（每次修改必须严格执行）

### 阶段 1：问题分析（禁止直接改代码）

用户提出修改需求后，**不得直接编辑任何文件**，先输出「问题分析」，固定包含以下 5 部分：

1. **需求理解**：用 1-3 句话复述要做什么、不做什么。
2. **涉及文件/模块清单**：列出预计改动的文件路径与类/方法；不改的相邻模块也需说明原因。
3. **潜在风险与影响范围**：功能、数据、配置、接口、定时任务、兼容性风险。
4. **建议修改方案**：按步骤编号，每步写清改哪个文件的哪个位置。
5. **待确认决策点**：编号列出（建议 ≤ 4 条），每条给出可选项与推荐项，便于用户一句话回复。

输出后**立即停止**，等待用户确认，不调用任何编辑/写文件工具。

用户确认的典型形式：`1同意 2选B 3继续`、`确认执行`、`按方案做`。

### 阶段 2：确认后执行

- 严格按已确认的方案执行，**不擅自扩大改动范围**，不做顺手重构、不格式化无关代码。
- 若执行中发现方案不可行（编译约束、依赖缺失、接口冲突、数据模型不匹配等），**立即停止**，回到阶段 1 说明原因与替代方案，等待再次确认；不得自行改道。
- 执行中若发现必须新增的改动点，作为新的决策点重新确认，不得先改后报。

### 阶段 3：修改后自动收尾（无需用户提醒）

每次修改完成后自动执行以下全部动作：

1. **更新修复记录**：在 `FIX_LOG.md` **追加**一条记录（不覆盖历史），字段：日期 / 问题描述 / 涉及文件 / 修改要点 / 验证结果。
2. **同步 README**：若改动涉及功能、接口、用法、配置项、依赖、目录结构、数据库表/字段、核心业务规则、类结构，更新 `README.md` 对应章节与目录链接；涉及技术债的，同步更新「技术债登记表」。
3. **基础自检**：
   - 编译检查：`mvn -DskipTests compile`（优先离线 `-o`，失败再联网；沙箱无法写 `~/.m2` 时如实说明）。
   - 静态检查：未定义变量、断裂引用、缺失 import/依赖、注解缺失、XML 与 Mapper 接口不一致、配置键拼写。
   - 测试：项目存在测试则运行 `mvn test`；有启动脚本/可运行环境则启动验证。
   - 若依赖 MySQL/Redis 而环境不可用，标注「未运行」并给出手动验证命令，不得谎报通过。
4. **输出「自检报告」**，固定格式：

```markdown
## 自检报告
- 编译：通过 / 失败（原因）
- 测试：通过 / 失败 / 未执行（原因）
- 启动：成功 / 失败 / 未执行（原因）
- 发现的问题：无 / 具体问题
- 建议手动验证：1. ...  2. ...
```

5. **收尾汇总**：改动文件清单 + 关键差异说明 + 自检报告 + 建议手动验证点。

### 阶段 4：放弃 / 回滚

- 用户回复「放弃」：不进行任何修改，简要说明已终止，不追加 FIX_LOG。
- 已改动后需回滚：优先使用 git，先给出 `git status` / `git diff` 结果与建议的回滚命令；**不得擅自执行** `git reset --hard`、`git checkout --`、`git clean -f`、force push 等破坏性命令，除非用户明确要求。
- 修改关键文件前，需在「问题分析」中说明可回滚方式（git 或备份）。

## 二、行为约束

1. **一次只处理一个修改任务**，不合并多个未确认需求；用户一次提多个需求时，拆成任务并逐个确认。
2. **不修改与当前任务无关的文件**，包括格式化、重命名、注释清理。
3. **不删除现有功能**，除非用户明确要求；技术债（TD-x）修复必须以用户点名或确认的条目为准。
4. **修改前说明备份/回滚方式**：`pom.xml`、`application.yml`、实体类、Mapper XML、启动类等关键文件必须提及。
5. **所有回答用中文**；分析简洁、决策点编号化，便于用户一句话回复。
6. **保持现有代码风格**：
   - 实体用 Lombok `@Data`（`ReportTask` 已统一）；
   - Service 实现继承 `ServiceImpl<Mapper, Entity>` 并实现接口；
   - 使用构造器注入（现有实现风格），避免字段注入新增；
   - 日志沿用项目现状，新增代码不引入 `System.out` 调试输出。
7. **不引入无关依赖**；确需新增依赖时，说明用途、版本、来源（阿里云仓库），并列为决策点。
8. **不提交/不生成无关产物**：`target/`、`export/*.xlsx` 等运行产物不纳入改动范围。
9. 纯提问、代码解释、只读分析**不触发**确认流程，可直接回答；但只要涉及文件改动，必须走阶段 1。

## 三、本项目技术底线（修改时必须遵守）

### 3.1 语言与框架

- **JDK 8**：禁止 Java 9+ 语法/API（`List.of`、`var`、文本块、`Map.of` 等）。
- **Spring Boot 2.7.18**：Servlet 使用 `javax.servlet.*`，禁止 `jakarta.*`。
- **构建**：Maven，依赖走阿里云仓库；不擅自升级 parent 版本。

### 3.2 配置

- `application.yml` 所有键名必须使用 **ASCII 连字符 `-`**，严禁 Unicode 全角减号 U+2011（曾导致全部配置绑定失效）。
- 新增配置项必须：yml 定义 + `@Value`/`@ConfigurationProperties` 引用 + README「配置参考」同步。
- 环境相关配置（数据库、Redis）不在代码中硬编码新增，统一走配置。

### 3.3 数据库与 ORM

- 表名/列名使用下划线，Java 字段使用驼峰；依赖 MyBatis-Plus 默认 `mapUnderscoreToCamelCase=true`。
- 实体必须：`@TableName("表名")` + `@TableId(type = IdType.AUTO)`（本项目表均为 `AUTO_INCREMENT`）。
- 自定义 SQL 放在 `src/main/resources/mapper/*.xml`，namespace 为 Mapper 接口全限定名；XML 语句与接口方法必须一一对应。
- `task_status` 是 **varchar**：SQL 比较必须用字符串（`task_status = 'RUN'`），**禁止**与数字 `1` 比较。
- `stat_date` 是 **varchar**：范围查询前必须 `LocalDate.format("yyyy-MM-dd")` 转字符串，禁止直接传 `LocalDate`。
- 数据库表/字段变更属于高风险：必须同步实体、Mapper 接口、XML、README，并作为决策点单独确认。

### 3.4 业务状态与异步

- 任务状态只能使用 `TaskStatusEnum` 的 `status` 值（`WAIT`/`RUN`/`SUC`/`FAIL`），禁止硬编码字符串或混用 `.name()`。
- `@Async` 方法禁止同类自调用：必须通过 `@Lazy` 注入的 `self` 代理调用，并显式指定线程池 `@Async("reportExportPool")`。
- 分布式锁沿用 Redisson，key 前缀 `report:export:lock:`；锁的等待/持有时间调整需说明理由。
- 定时任务 cron 属调试值（`*/30 * * * * ?`），修改需用户确认并同步 README「类速查表」。

### 3.5 Excel 导出

- `LocalDateTime` 字段必须加 `@DateTimeFormat("yyyy-MM-dd HH:mm:ss")`，否则 EasyExcel 运行时报错。
- 导出模型字段必须有中文 `@ExcelProperty`，禁止依赖英文字段名作为列头。
- 导出文件路径约定 `{user.dir}/export/{taskId}.xlsx`；改动命名规则需同步 README「核心业务规则」。

### 3.6 接口与安全

- Controller 统一 `@RestController` + 类级 `@RequestMapping` 前缀；新增接口需同步 README「后端接口清单」。
- 参数校验使用 `@Validated` 等标准注解；当前项目未引入 validation starter，新增前需确认依赖。
- 不新增明文密钥/口令；现有 `application.yml` 明文仅限本地开发，不在代码与文档中扩散。

## 四、自检与验证命令

```powershell
# 编译（优先离线，失败再联网）
mvn -o -DskipTests compile
mvn -DskipTests compile

# 测试
mvn test

# 启动（依赖 MySQL + Redis）
mvn spring-boot:run

# 接口快速验证
Invoke-RestMethod -Method POST -Uri "http://localhost:8080/report/export/submit" -ContentType "application/json" -Body '{"startDate":"2026-02-01","endDate":"2026-05-31"}'
Invoke-RestMethod -Uri "http://localhost:8080/report/export/query?taskId=<taskId>"
Invoke-WebRequest -Uri "http://localhost:8080/test/mapper" -UseBasicParsing
```

> 沙箱可能限制 `~/.m2` 写入或访问外网；如遇此类失败，需明确说明是环境限制，并给出手动执行步骤。

## 五、文档同步规则

| 改动类型 | 必须同步位置 |
|---|---|
| 任何代码修改 | `FIX_LOG.md`（追加） |
| 新增/修改接口 | README「后端接口清单」 |
| 新增/修改配置项 | README「配置参考」 |
| 依赖/版本变化 | README「技术栈 & 依赖」+ `pom.xml` |
| 新增类/Job/Mapper | README「目录结构」「类速查表」 |
| 业务规则变化 | README「核心业务规则」「开发约定」 |
| 修复技术债 | README「技术债登记表」移除该条 + 「Bug 修复历史」补记录 |
| 表结构变化 | README「数据库表结构」「实体 ↔ 表字段映射」 |

## 七、例外与边界

- 用户明确说「直接改，不用分析」时，可跳过阶段 1，但仍须在改动前一句话说明范围，并在完成后执行阶段 3 收尾。
- 极小改动（错别字、注释、日志文案）仍需在问题分析中标注「极低风险」，等确认后执行。
- 用户回复「放弃」即终止任务；不得继续试探性修改。
